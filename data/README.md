# Тестовые данные

Выдуманные цели для проверки ядра, консоли и окна. Формат одинаковый:

```
id,type,x,y,altitude,speed,heading
```

`id` — целое и уникальное, `type` — `aircraft` | `helicopter` | `drone`, `x`/`y` — км (x на восток, y на север), `altitude` — км, `speed` — км/ч, `heading` — градусы (0° = север, по часовой стрелке).

Все расстояния и пары ниже посчитаны и проверены — можно сверять вывод программы с этой таблицей.

## `sample.csv` — основной набор, 10 целей

| id | x, y | расстояние до (0,0) | ближе 50 км |
|---|---|---|---|
| 1 | 3, 4 | 5.000 | да |
| 2 | 10, 0 | 10.000 | да |
| 3 | 0, −20 | 20.000 | да |
| 5 | −25, 0 | 25.000 | да |
| 4 | 20, 20 | 28.284 | да |
| 6 | 30, 45 | 54.083 | нет |
| 7 | 0, 60 | 60.000 | нет |
| 9 | 70, 0 | 70.000 | нет |
| 8 | −50, −50 | 70.711 | нет |
| 10 | 0, −80 | 80.000 | нет |

Что проверяет:

- **чтение**: 10 строк файла → 10 целей;
- **сортировка по расстоянию** — строки должны идти в порядке из таблицы (5, 10, 20, 25, 28.284, 54.083, 60, 70, 70.711, 80);
- **фильтр «ближе 50 км»** — ровно 5 целей (id 1, 2, 3, 4, 5);
- **нормализация курса**: у id 5 курс 370° (= 10°), у id 6 курс −10° (= 350°) — при движении они должны вести себя как нормализованные;
- **разные направления**: есть цели на всех четырёх сторонах света — удобно проверять радар (0° вверх, 90° вправо).

## `dense.csv` — сближения, 11 целей

Пары, посчитанные по координатам:

| Пара | Расстояние | Порог 10 км |
|---|---|---|
| (1, 2) | 5.00 | конфликт |
| (3, 4) | 8.00 | конфликт |
| (8, 9) | 9.90 | конфликт (граница «снизу») |
| (10, 11) | 10.10 | **не** конфликт (граница «сверху») |

Что проверяет: `findConflicts(tracker, 10.0)` должен вернуть ровно три пары — (1,2), (3,4), (8,9) — и **не** вернуть (10,11).
Это и есть проверка строгого порога: 9.9 — да, 10.1 — нет.

## `edge.csv` — границы, 5 целей

| id | x, y | расстояние | что проверяет |
|---|---|---|---|
| 1 | 30, 40 | 50.000 | ровно на границе фильтра: при «строго меньше 50» — **не** проходит |

| 3 | 0, 50.1 | 50.100 | не проходит фильтр |

Плюс курсы для проверки нормализации: 370° (id 1), −10° (id 2), 720° (id 3), 360° (id 4).

## `bad.csv` — испорченная строка

Строка 4 файла (третья строка данных): `3,aircraft,abc,40,7,650,270` — в поле `x` текст вместо числа.
Ожидание: `loadTargets` бросает исключение, в сообщении есть `line 4`. Программа печатает сообщение и возвращает код 1 — без падения.

Внимание: номер строки считается по файлу, где строка 1 — заголовок. Третья строка данных — это 4-я строка файла.

## `empty.csv` — только заголовок

Ожидание: чтение возвращает пустой вектор, исключения нет, программа печатает «0 целей» и не падает.

## Как запускать

Программа ищет файл по относительному пути от **каталога запуска**, а не от корня проекта. Надёжнее:

- из консоли — запускать из корня репозитория (`air-tracker`), тогда `data/sample.csv` находится;
- в Qt-версии — выбирать файл через диалог, а не хардкодить путь.
